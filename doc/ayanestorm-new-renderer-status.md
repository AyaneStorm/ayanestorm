- **Occlusion is proved, not assumed:** `--audit` culls again with no occlusion test after each frame, and draws that against the final depth. Any pixel that gets through belongs to a cluster that was wrongly hidden. It found 0 such pixels on either platform, from above and at street level, over about 1,600 frames with the camera and objects moving. It is a pass of the graph with its own sink, so a normal frame runs none of it.
- **Two-phase design:** the first phase tests against last frame's depth pyramid, using this frame's object positions. What it hides goes on a retest list, and is tested again against a pyramid of the new depth. So a wrong guess from last frame costs extra drawing and can never lose anything, and no per-cluster memory of what was seen is needed. A whole hidden instance takes one retest entry, so its clusters are not walked twice.
- **The pyramid is a plain buffer:** each level rounds its size up, so a texel always covers exactly its 2x2 below, with no special cases at odd sizes and no image views or layout changes per level, on either API. One dispatch makes three levels, so a full chain takes four dispatches at 2560x1440. It costs about 0.1 ms per build on the 3080 Ti, and it is built twice per frame.
- **Frame graph:** `asrframegraph` holds the passes and what each uses, and `asrscenegraph` declares the scene's passes once for both backends. All Vulkan barriers now come from those declarations. Replacing a pass and adding after one are both tested. Unused passes do not run, and a result made twice is an error when the graph compiles. Results kept until they change are in place and tested, for the shadow cache to use. Metal orders passes by one fence, so it ignores the transitions.
- **Still to do in the graph:** target aliasing (section 6a) waits for P4, because none of today's targets have lifetimes that do not overlap. The composite and UI stay outside the graph and read the G-buffer as a sink. A view running twice in one frame is not flagged yet: only one view exists until snapshots and probes.
- **LOD:** a geometry can name a coarser one, and the cull shader walks that chain from distance divided by object size, so a chain needs no CPU work per frame. An LOD that is still uploading is skipped in either direction, so an object shows whatever has arrived. All LODs of a face must be packed in the same box, because an instance's matrix holds that box. For viewer content that box should be the object's unit cube, to confirm in step c. Each instance has its own `lodCenter` and `lodSize`, so all faces of an object choose together, which leaves no cracks between faces.
- **Kinds of surface:** masked and double-sided are instance flags, so culling reads no material, and each of the 4 kinds has its own 4 lists: 16 draws per phase, all indirect. Double-sided clusters skip the facing test, and the resolve turns their normals around on the back. Masked fragments discard before writing depth, so a hole hides nothing from occlusion. The back-side normal has not been checked on its own: the picture looks right, but no test looks at that side alone.
- **Removing geometry:** removal now waits for the last instance and the last finer LOD, because an id reused too early would corrupt the counts behind list sizes.
- **Pass timers are right:** the plan doubted a resolve of 0.08 ms at 2560x1440. Running it 11 times per frame moved the timer to 1.00 ms and the frame from 0.91 to 1.81 ms, so the figure was true. The timers add up to the frame time on Vulkan. Metal samples encoder edges, and draws report vertex and fragment work apart. On the M4, in a run with validation on, about 95% of a draw's time was vertices.
- **New Vulkan requirement:** `shaderDemoteToHelperInvocation`, which glslang uses for `discard`. Vulkan 1.3 requires every device to have it.
- **Why addresses, not bindings:** tables and geometry are reached by device address from push constants, so a growing table needs no rebinding, and one GLSL source became valid Metal through SPIRV-Cross on the first try, including atomics and `textureGrad` in compute. Metal cannot see which buffers a shader reaches this way, so one `MTLFence` orders the passes by hand.
- **Geometry memory:** 64 MB chunks that never move, so clusters can hold addresses. The city takes 77 MB of geometry. A moved object writes one 64-byte entry, and several moves between two frames are merged into one write.
- **Uploads cannot stop the renderer:** the first version could: 64 MB of textures plus 64 MB of scene data per frame slot exceeds the staging budget even at 12 GB. Now one frame's upload share is fixed at startup from the staging budget, so every frame in flight fits. Instances that do not fit wait for the next frame, in order, and a large texture goes up in bands of rows over several frames. At a 4 GB cap the city and a 4096x4096 texture load normally. At 300 MB, far below the floor, geometry waits and nothing fails.

- **Step d, mesh and sculpts, written on 7 November, not built, nothing tested:**
  - **Repeated mesh is one shape:** `ShapeKey` is the mesh's asset ID alone, as the profile and path an object carries change nothing. A field of 5,000 copies stores its geometry once and costs one instance per face per copy. `Shape::users` replaces the count and `waiting`.
  - **LODs are built coarsest first:** a mesh's LODs arrive in any order, and an instance names the head of a chain that cannot be changed in the middle. So an object asks for every LOD from 0 up to its own, all at once, and `arrived` holds what comes early. `startNextMeshLod()` builds them in order, one job per shape at a time, so the chain only grows at its fine end and never has a hole. This also means the GPU always has the right coarse LOD. The cost is the coarser LODs' download, which OpenGL skips for near objects.
  - **Missing LODs:** a header can show a LOD does not exist, and such a request is dropped without a reply. `getActualMeshLOD()` skips those, and `wantMeshLods()` runs again when the header arrives. `meshUnavailable()` covers failed ones.
  - **Fixed box:** all LODs of a face share one box and later ones are unknown, so mesh uses the object's unit cube. All faces then share one position grid, so seams cannot crack. A 64 m mesh gets 1 mm steps, and tiny details on a huge mesh are the case to watch.
  - **Workers own a copy:** `ShapeJob` carries a copy of `faces`, and the main thread takes it back, because the main thread reads `Shape::faces` while later LODs build. The hook sits last in `notifyMeshLoaded()`, because `createTangents()` changes the volume the viewer copies from.
  - **LOD sweep replaces `updateDistance`:** `sweepLods()` sets `mDistanceWRTCamera` and calls `updateLOD()` for objects in view, walking all objects over 0.25 s. `updateCull()` does not run here, so nothing did this before. The distance is taken from the object's position, which is where the GPU measures from. It keeps picking on the right LOD too, and also gives the viewer real distances where they stayed at 0, which may change texture priorities.
  - **Bursts:** `applyChanges()` spends at most 4 ms per frame. A finer LOD with the same face count only rewrites instances through `sMoved`, so a repeated mesh does not go through its materials again.
  - **Shape changes:** `WorldObject::next` keeps the old shape in sight until the new one is built, for sculpts as they sharpen and for prims being edited.
  - **Sculpts:** the shape key adds the sculpt level, and all four LODs are built on a worker from a copy of the map. An object waits under `sculpt map` until the viewer has sculpted it once. No map in memory draws what the viewer draws with no data.
  - **Still left out:** rigged, attached and animated objects (step e), flexible prims, glTF objects. No finer LOD is ever dropped once a mesh is far away, so geometry memory only falls when an object goes: step f owns that.

- **How draws merge:** vertices are transformed as they are copied, strips and fans become plain triangles, and each vertex carries its texture slot, sampler and solid-color bit. So matrix and texture changes never split a draw.
- **Metal needs macOS 15:** residency sets make a bindless texture cost nothing per frame, so the probe refuses older systems and the viewer stays on OpenGL there.
- **How the viewer reaches the renderer:** `llrender` is built with or without `AS_RENDERER`, so it talks to a small interface in `asrbridge.h`, which `asrviewer.cpp` fills in. Only `.cpp` files include it, so `llrender.h` and `llvertexbuffer.h` stay untouched and a change here never rebuilds the viewer. One virtual call per flush costs nothing next to the vertex work behind it.
- **Textures are handed over in `LLImageGL`, not in `glTexImage2D`:** `setImage()` and `setSubImage()` pass the pixels straight on, and the GPU makes the mips, which also skips the CPU mip loop. A name maps to its slot and sampler through one array read at draw time. `LLTexUnit` reports wrap and filter per texture. `ASRGLTable` only keeps what GL state it is the natural owner of: blend, scissor, and texture names. `setManualImage()` does nothing in this mode: what still reaches it is render targets and world data.
